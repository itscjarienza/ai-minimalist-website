The Problem

A lot of businesses are paying for AI.
Far fewer are implementing it well.

The pattern is predictable. A team buys access to a tool. Nobody defines the exact job. Nobody owns review. Nobody tracks whether the thing is actually saving time or moving a number that matters.

That's not a rollout. That's drift.

Six months in, the tool is still on the credit card, the team is using it inconsistently, and nobody can say whether it was worth it.

The fix isn't another tool. It's a clear question asked before the purchase — and a way to answer it honestly.

What It Is

One page. Seven fields. One decision.

01
Define the workflow and the job to be done.

Name the business process you're improving and write the AI's role in one sentence. If you can't do that, you're not ready to implement.

// "drafts a first-pass proposal from intake notes" is a job. "helps with proposals" is not.

02
Define the input and the expected output.

What does AI need to do the job? What should the finished result look like? Both fields are required. If either is vague, the implementation will be too.

03
Name the reviewer and the success metric.

One person owns review. One metric tells you whether the tool is earning its place. Time saved, output quality, throughput — something you can actually check in 30 days.

// no reviewer + no metric = no way to validate, no way to cut it if it fails

04
Make the keep / pause call.

After 30 days, does it pass? The scorecard gives you a simple lens: keep if the metric moved, pause if it didn't. No ambiguity, no inertia.
